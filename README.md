# WukongBench

Консольная программа на C#. Сама проводит два прогона Black Myth: Wukong Benchmark Tool из Steam (CPU-тест и GPU-тест) и печатает характеристики компьютера, результаты и настройки каждого прогона.

## Что нужно

- Windows и .NET 10 SDK
- Steam запущен, вход выполнен
- Benchmark Tool установлен, один раз запускался вручную и сейчас закрыт

## Запуск

Из корня репозитория:

```
dotnet run --project src/WukongBench
```

Работа занимает около 7 минут. Утилита на это время занимает экран, нажимать ничего не нужно.

Параметры, оба необязательные:

```
--tool-dir <папка>       папка утилиты, если её не удалось найти через Steam
--profiles-dir <папка>   свои профили, один файл .ini на прогон
```

Отчёт идёт в стандартный вывод, журнал хода работы в поток ошибок. Сохранить их в файлы можно так (из cmd):

```
dotnet run --project src/WukongBench > report.txt 2> log.txt
```

Код возврата 0, если все прогоны удались, иначе 1.

## Что делает программа

1. Находит утилиту через Steam и собирает сведения о компьютере.
2. Сохраняет копию файла настроек утилиты.
3. Для каждого профиля записывает настройки, запускает утилиту с параметром `-benchmark`, ждёт файл результатов и закрывает утилиту.
4. Возвращает настройки утилиты и печатает отчёт.

В отчёте четыре таблицы: система, результаты прогонов, настройки из профилей и настройки, которые записала сама утилита.

## Настройки прогонов

Профили лежат в [src/WukongBench/Settings/Profiles/Default](src/WukongBench/Settings/Profiles/Default), по файлу на прогон.

### CPU-тест (01-cpu.ini)

Задача: оставить видеокарте как можно меньше работы, чтобы FPS зависел от процессора.

| Настройка | Ключи в профиле | Значение | Почему |
|---|---|---|---|
| Режим экрана | `FullscreenMode`, `LastConfirmedFullscreenMode`, `ScreenMode` | 2, окно | Вывод во весь экран сам нагружает видеокарту |
| Размер окна | `ResolutionSizeX`, `ResolutionSizeY` и их пары `LastUserConfirmed...` | 1280x720 | Маленькое окно, меньше работы на выводе |
| Размер рендера | `DesiredScreenWidth`, `DesiredScreenHeight` и их пары `LastUserConfirmed...` | 640x360 | Минимум, который допускает движок |
| Масштаб в отчёте утилиты | `ImageQuality` | 360 | Чтобы утилита показала настоящий масштаб, 50% |
| Качество: дальность прорисовки, сглаживание, тени, освещение, отражения, постобработка, текстуры, эффекты, растительность, материалы | `sg.ViewDistanceQuality`, `sg.AntiAliasingQuality`, `sg.ShadowQuality`, `sg.GlobalIlluminationQuality`, `sg.ReflectionQuality`, `sg.PostProcessQuality`, `sg.TextureQuality`, `sg.EffectsQuality`, `sg.FoliageQuality`, `sg.ShadingQuality` | 0, минимум | Каждая из них добавляет работу видеокарте |
| Трассировка лучей | `sg.RayTracingQuality` | 0, выключена | Нагрузка на видеокарту |
| Генерация кадров | `InsertFrame` | 0, выключена | Завышает FPS вдвое |
| Размытие в движении | `MotionBlur` | 0, выключено | Лишняя работа видеокарты |
| Вертикальная синхронизация | `bUseVSync`, `Vsync` | выключена | Иначе результат упрётся в частоту монитора |
| Ограничение FPS | `FrameRateLimit`, `LockFrameRate` | 0, без ограничения | Иначе результат упрётся в ограничитель |
| Динамическое разрешение | `bUseDynamicResolution` | выключено | Иначе размер рендера меняется по ходу теста |

### GPU-тест (02-gpu.ini)

Задача: нагрузить видеокарту максимально.

| Настройка | Ключи в профиле | Значение | Почему |
|---|---|---|---|
| Режим экрана и разрешение | не заданы | как в утилите | Тест идёт в разрешении, выбранном в утилите. По умолчанию это родное разрешение монитора |
| Размер рендера | `DesiredScreenWidth`, `DesiredScreenHeight` и их пары `LastUserConfirmed...` | `{ResolutionSizeX}` x `{ResolutionSizeY}`, то есть разрешение экрана | Масштаб 100%, без апскейла |
| Масштаб в отчёте утилиты | `ImageQuality` | `{ResolutionSizeY}` | Чтобы утилита показала настоящий масштаб, 100% |
| Качество: дальность прорисовки, сглаживание, тени, освещение, отражения, постобработка, текстуры, эффекты, растительность, материалы | `sg.ViewDistanceQuality`, `sg.AntiAliasingQuality`, `sg.ShadowQuality`, `sg.GlobalIlluminationQuality`, `sg.ReflectionQuality`, `sg.PostProcessQuality`, `sg.TextureQuality`, `sg.EffectsQuality`, `sg.FoliageQuality`, `sg.ShadingQuality` | 4, максимум | Утилита записывает такой прогон как максимальный пресет |
| Трассировка лучей | не задана | как в утилите | См. выводы |
| Генерация кадров | `InsertFrame` | 0, выключена | Завышает FPS вдвое |
| Размытие в движении | `MotionBlur` | 2, максимум | Дополнительная работа видеокарты |
| Вертикальная синхронизация | `bUseVSync`, `Vsync` | выключена | Иначе результат упрётся в частоту монитора |
| Ограничение FPS | `FrameRateLimit`, `LockFrameRate` | 0, без ограничения | Иначе результат упрётся в ограничитель |
| Динамическое разрешение | `bUseDynamicResolution` | выключено | Оно снижает размер рендера, когда видеокарта не справляется |

## Выводы

Загрузку видеокарты во время прогонов дополнительно мерили через nvidia-smi, загрузку процессора по времени процесса утилиты.

### CPU-тест

- Время кадра процессора и видеокарты почти сравнялось. Процессор загружен заметно: четыре ядра, самый нагруженный поток на 82%.
- Полностью убрать влияние видеокарты на этой машине не вышло. GTX 1070 и при таких настройках занята на 95%, а снизить нагрузку дальше настройки утилиты не позволяют. С более быстрой видеокартой тот же профиль должен упираться в процессор, проверить это было не на чем. Поэтому в отчёте время кадра процессора и видеокарты стоит рядом: по нему видно, что ограничивало прогон.
- Окно вместо полного экрана подняло FPS на 13%.
- Рендер 640x360 вместо 1280x720 поднял FPS на 52%. Ниже 360 строк движок не опускается, даже если задать меньше.
- Все настройки качества нужно держать на минимуме. С тенями, растительностью и дальностью прорисовки на «ультра» было 37 FPS, с ними же на минимуме 65.
- В режиме «окно без рамок» ключи `ResolutionSizeX` и `ResolutionSizeY` размер картинки не меняют, окно остаётся размером с рабочий стол. Поэтому тест идёт в обычном окне.
- Минимум 16 FPS это единичный провал. В двух других прогонах с теми же настройками минимум был 34 и 58, а 5-й перцентиль во всех трёх около 100.

### GPU-тест

- Тест упирается в видеокарту. Она занята на 99%, её кадр в девять раз длиннее кадра процессора, процессор почти простаивает.
- Масштаб 100% удлиняет кадр видеокарты на 32% по сравнению с масштабом 67%, который утилита ставит на этой машине по умолчанию.
- Трассировка лучей в профиль не включена. GTX 1070 её не поддерживает, и принудительное включение нагрузку не подняло, а снизило: 25 FPS вместо 17. При этом утилита записала трассировку как включённую. На видеокарте с поддержкой трассировки проверить было не на чем. Включить её вручную можно строками `Rtx=1` и `RtxLevel=3` в секции `[UISettingData]` профиля.

### Общее для обоих профилей

- Генерация кадров в утилите включена по умолчанию и завышает FPS вдвое. При настройках по умолчанию утилита показала 71 FPS, а настоящих кадров было 36 в секунду. Поэтому в обоих профилях она выключена.
- Стандартный для Unreal ключ `sg.ResolutionQuality` утилита не учитывает. Размер рендера задают `DesiredScreenWidth` и `DesiredScreenHeight`.
- Поля загрузки процессора и видеокарты в результатах утилиты загрузку не отражают: процессор всегда 1, видеокарта 19-41 при реальных 95-99%. В отчёт программы вместо них идёт время кадра.
- Время кадра процессора почти не зависит от настроек: от 7,3 до 8,5 мс во всех прогонах.

## Как это устроено

### Как утилита хранит настройки

Файл один: `b1\Saved\Config\Windows\GameUserSettings.ini` в папке утилиты. Но разные настройки она читает из разных его частей:

- качество: ключи `sg.*` в секции `[ScalabilityGroups]`
- режим экрана, разрешение и размер рендера: обычные ключи первой секции
- генерация кадров, размытие, синхронизация, ограничение FPS: пары внутри строки `UISettingData`

Значение `ImageQuality` из `UISettingData` меняет только масштаб, который утилита показывает в своих результатах, на сам рендер оно не влияет.

При выходе утилита пересохраняет файл настроек. Программа перед правкой делает его копию и возвращает её после каждого прогона и в конце работы. Если программу прервали, копия остаётся рядом с файлом, и следующий запуск восстановит настройки из неё.

### Запуск утилиты и результаты

Утилита запускается командой `b1_benchmark.exe -benchmark`. С этим параметром тест начинается сам, без заставки, меню и подтверждения. В окружении процесса заданы `SteamAppId` и `SteamGameId`. Без них утилита перезапускает себя через Steam, и тот просит подтвердить запуск.

После теста утилита пишет JSON в `%TEMP%\b1\BenchMarkHistory\Tool`, по файлу на прогон, и хранит пять последних. Программа ждёт появления нового файла до 15 минут, читает из него итоги, настройки прогона и покадровые записи, потом закрывает окно утилиты. Время кадра процессора и видеокарты в отчёте считается как среднее по покадровым записям.

### Формат профиля

Профиль это файл `.ini`. Прогоны идут в порядке имён файлов. Секции и ключи те же, что в файле настроек утилиты, плюс два дополнения:

- секция `[UISettingData]` меняет значения внутри одноимённой строки файла настроек
- значение вида `{Ключ}` берётся из самого файла настроек, например `DesiredScreenWidth={ResolutionSizeX}`
